Eventos en React

Los eventos permiten que la interfaz responda a las acciones del usuario: clics, escritura en un campo, envío de un formulario. En React se asignan como atributos del elemento con nombres en camelCase.

function Boton() {
  const saludar = () => alert("Hola");

  return <button onClick={saludar}>Saludar</button>;
}

Renderizado condicional e iterativo

❓

Condicional

Mostrar u ocultar elementos según una condición, con && o el operador ternario ? :.

🔁

Iterativo

Generar una lista de elementos a partir de un arreglo con map(). Cada elemento lleva una key única.

{logueado ? <Panel /> : <Login />}

<ul>
  {usuarios.map((u) => (
    <li key={u.id}>{u.name}</li>
  ))}
</ul>

Formularios y Routing

  • ⌨️
    Formularios

    Se capturan los datos de los campos con eventos como onChange y onSubmit.

  • 🧭
    Routing

    Permite navegar entre vistas de una aplicación de una sola página sin recargar el navegador.

🌐

Consumo de APIs

Una API entrega datos desde un servidor. Como la respuesta no es inmediata, se trabaja con operaciones asíncronas.

🤝

Promesas

Objetos que representan un resultado futuro. Se encadenan con .then() y .catch().

⏳

Async / Await

Sintaxis que permite escribir código asíncrono con apariencia secuencial.

📡

Axios

Librería para hacer peticiones HTTP de forma más sencilla que fetch.

import axios from "axios";

async function cargarUsuarios() {
  try {
    const res = await axios.get("https://jsonplaceholder.typicode.com/users");
    setUsuarios(res.data);
  } catch (error) {
    console.error(error);
  }
}

03

Reflexión Metacognitiva

💡

¿Qué aprendí?

Aprendí a manejar eventos en React, a mostrar contenido según condiciones y a recorrer listas con map(). También a consumir datos de una API con promesas, async/await y Axios.

🎯

¿Cómo lo aprendí?

Con la teoría del docente y desarrollando el laboratorio: pedí datos a una API, los mostré en pantalla y probé cada evento hasta que la aplicación respondió como esperaba.

🧭

¿Para qué me sirve?

Para conectar el frontend con un servidor y mostrar datos reales. Es justo lo que necesito en mis proyectos fullstack, donde la interfaz consume la API del backend.

🧩

¿Qué dificultades tuve?

Entender el comportamiento asíncrono: los datos no llegan al instante, y hay que manejar el caso de espera y de error.

🛠️

¿Cómo las superé?

Usando console.log para ver la respuesta de la API, separando la carga de datos del renderizado y probando con try/catch.

🚀

¿Cómo lo aplicaré?

En mis proyectos con backend propio y como base para los hooks de la semana 7, como useState y useEffect, que son los que manejan el estado y la carga de datos.
